### 一、短链跳转：拿到真实作品 ID

抖音分享出来的链接长这样：

```
https://v.douyin.com/xxxxxxx/
```

这个短链里没有任何可用信息。真实作品 ID（下称 `aweme_id`）藏在跳转之后。

```python
resp = session.get(short_url, allow_redirects=False, timeout=10)
location = resp.headers.get("Location", "")
```

**第一个坑**：不要用 `allow_redirects=True` 一把梭。
实践中短链可能出现多次跳转，而且中间会插入风控用的中间页，
一把梭跟到最后拿到的 URL 里可能根本没有 ID。
正确做法是**逐跳处理，每一跳都记下来**，从最后一跳里正则提取：

```python
m = re.search(r"/video/(\d+)", final_url) or re.search(r"modal_id=(\d+)", final_url)
```

**第二个坑**：分享文案里的链接经常是「复制此条信息，打开抖音App」这种形态，
URL 后面跟着中文文案，有的还夹了不可见的 Unicode 字符。
提取之前先把整段文本过一遍正则拿 URL，再处理，不要直接 `get()` 原始输入。

### 二、登录态：这一步绕不过去

这是最容易被低估的一环。很多教程会告诉你「不带 Cookie 也能抓」，
在 2024 年之前可能成立，现在不行了。实测结果：

| 请求形态 | 接口返回 |
|---|---|
| 完全无 Cookie | 响应体为空 |
| 游客态 ttwid | `filter_reason=core_dep` |
| 未签名请求 | 风控码 2483 |
| 有效登录态 + 签名 | 正常数据 |

**结论：拿到真实登录态是唯一可行的路子。**

获取方式上我试过三种：

1. **手动从浏览器复制** —— 可行但体验极差，用户要按 F12、找请求头、复制一大串字符串，
   任何一个环节走错就失败。而且 Cookie 会过期，用户过几天又要来一遍。
2. **Playwright 内置 Chromium** —— 体验最好，点一下按钮扫码就完事，
   代价是 Chromium 独占 **719 MB**，整个程序装完 944 MB。
3. **Playwright 调用系统浏览器** —— 折中方案。

最终选了第 3 个：

```python
# 按优先级找本机已装的浏览器
for channel, paths in (("msedge", EDGE_PATHS), ("chrome", CHROME_PATHS)):
    if any(os.path.isfile(p) for p in paths):
        browser = p.chromium.launch(headless=True, channel=channel)
        break
```

Win10/11 自带 Edge，装机率接近 100%，这条路径对绝大多数用户是通的。
只有系统里两个都没有时，才退回手动粘贴。

**第三个坑**：扫码登录要判断的是**是否真的登录了**，
而不是「浏览器打开成功了」。我一开始就栽在这里——
浏览器起来了，但用户没扫，拿到的 Cookie 是游客态，
后面所有请求全部返回空，错误信息还特别具有误导性。

正确做法是检查具体的登录态字段：

```python
LOGIN_KEYS = ("sessionid", "sessionid_ss", "sid_tt", "passport_csrf_token")

def has_valid_login_cookie(cookies):
    for c in cookies:
        if c["name"] in LOGIN_KEYS and c["value"] and len(c["value"]) > 20:
            return True
    return False
```

拿到之后序列化成请求头存到本地，之后长期复用。

### 三、请求签名：只讲思路

详情页接口要求请求参数带签名（业界俗称 a_bogus / X-Bogus）。
这里**只讲思路，不贴实现**，原因有两个：
一是贴出来会加速失效，二是这套本来就属于对方的风控资产。

大方向是这样的：

1. 把业务参数按字典序排列，拼成查询串
2. 与 User-Agent、时间戳等一起参与混淆
3. 经过若干轮自定义的位运算与查表，生成固定长度的签名串
4. 追加到查询串末尾

逆向的主要成本不在算法本身，而在**定位加密函数**——
混淆后的 JS 里函数名叫 `_0x1a2b` 这种，得靠调用栈和特征字符串去锚。

**第四个坑**：签名依赖 User-Agent。
请求时的 UA 必须和生成签名时用的一致，差一个字符就 403。
我的做法是把 UA 当常量全局共用，不在任何地方二次生成。

### 四、数据结构：无水印直链藏在哪

拿到详情 JSON 后，关键路径：

```python
aweme    = data.get("aweme_detail") or {}
# 视频
uri      = aweme["video"]["play_addr"]["url_list"][0]
# 图集
images   = aweme.get("images") or []
```

这里有个容易踩空的点：**`url_list` 里第一个 URL 未必是最终地址**，
它可能还要再跳一次 CDN。下载时必须 `stream=True` 跟着重定向走。

**水印问题**：返回的直链本身就是无水印的原文件。
水印是播放器在渲染时叠的一层，不在文件里。
所以"去水印"这个说法其实不准确，我们做的是**拿到播放器拿到之前的那份文件**。

**第五个坑**：图集和视频是两套结构。
判断依据是 `images` 字段是否存在，存在就是图集，
千万不能用 `aweme_type` 猜——实测它对不上。

互动数据在同一个对象里：

```python
stats = aweme.get("statistics") or {}
digg    = stats.get("digg_count")      # 点赞
comment = stats.get("comment_count")   # 评论
share   = stats.get("share_count")     # 转发
collect = stats.get("collect_count")   # 收藏
```

### 五、体积优化：719 MB → 59 MB

这是整个项目里最有意思的一段。

第一版打包出来 **342 MB 安装包 / 944 MB 安装后**，其中 Chromium 独占 719 MB。
一个下载 5 分钟、安装 5 分钟的东西，转化率必然难看。

优化路径是把内置 Chromium 换成调用系统浏览器：

| 版本 | 安装包 | 安装后 | 功能 |
|---|---|---|---|
| 完整版（内置内核） | 342 MB | 944 MB | 全 |
| 精简版（借系统浏览器） | 59 MB | 223 MB | **完全一致** |

**第六个坑（也是最蠢的一个）**：
我一开始对"精简版"的理解是「把登录功能砍掉」，
于是设了个 `DISABLE_LOGIN` 开关，精简版直接不支持自动获取 Cookie——
结果就是**精简版根本解析不了任何东西**，因为登录态是硬需求。

这是个典型的把"精简"和"阉割"搞混的错误。
后来改成借用系统浏览器，砍的是 719 MB 的浏览器体积，
功能一个没少。体积和体验不必然互斥。

教训：**先确认哪些是硬依赖，再谈裁剪。**
把硬依赖当成可选功能砍掉，得到的是一个能装上、但什么都干不了的废品。

### 六、踩坑清单（速查）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | 短链一把梭跟跳转 | 拿不到 ID | 逐跳处理，最后一跳才提取 |
| 2 | 分享文案夹带中文和不可见字符 | 正则匹配失败 | 先从文本里抽 URL 再处理 |
| 3 | 浏览器起来了但没扫码 | 全部请求返回空 | 检查具体登录态字段，别只看进程 |
| 4 | 签名与 UA 不一致 | 403 | UA 设成全局常量 |
| 5 | 用 `aweme_type` 判断图集 | 类型判断错误 | 看 `images` 字段存不存在 |
| 6 | 把硬依赖当可选功能砍掉 | 软件能装但不能用 | 裁剪前先分清硬依赖与可选项 |

### 七、关于图形界面

工具最终用 PySide6（Qt6）做壳，原因很实际：
这类工具的使用者是运营、剪辑，不是开发，命令行没有转化率可言。

两个值得一提的取舍：

- **耗时操作一律丢 QThread**，解析和下载都走信号回主线程，界面不卡死
- **记录本地持久化**，列表误删可恢复——用户最怕的不是功能少，是"我辛辛苦苦攒的记录没了"
